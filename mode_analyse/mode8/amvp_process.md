# mode 8：ME 后无模板决策树加权八选二

源码核验更新：2026-10-04。算法解释依据当前源码；实测结果对应已存在的测试批次，不表示本次重新编码。跨模式索引、ME 与日志术语见 [共同机制](../amvp_common_mechanisms.md)。

实现日期：2026-10-02。编码器和解码器均指定 `--amvpmode=8`。
模式值不写入码流；正式 AMVP 列表仍只有两个候选，仍使用原有 0/1 索引和 MVD。
模型来自离线训练，编解码器使用同一份固定节点表，无需逐块 sidecar 或运行时训练库。

## 候选构造与共享信息

沿用 mode 7 的固定八位置池：保留标准 AMVP 的原始 0/1，按已有空域、时域、HMVP
探测顺序补入不同 MV，不足时补零。纯填充零不参与投票或中心选择；合法派生零正常参与。
有效运动不足两个时，保留原始两个正式位置。

每项同时保存来源集合（空域=1、时域=2、历史=4）、独立邻接 CU 支持数量和最近匹配
HMVP 年龄（0 为最新）。来源可以重叠；同邻接 CU 的多位置探测不能重复增加支持数。
按当前 AMVR 码字精度稳定去重，合并来源，支持数使用该码字运动的独立 CU 集合，历史
年龄取最近值。同数值运动只投一票，最早的原始位置成为代表。

这些元数据由 CommonLib 共享构造，mode 8 关闭 `AmvpTrace` 时也必须获得同样的值。

## 固定特征 ABI

树输入只有 12 个整数，顺序与 `AmvpDecisionTree.h` 完全一致：

| 序号 | 特征 | 单位/缺失值 |
|---:|---|---|
| 0 | 当前 IMV | 0/1/2/3 |
| 1 | CU 宽度的 log2 | 整数 |
| 2 | CU 高度的 log2 | 整数 |
| 3 | 有效唯一运动数 | 0..8 |
| 4 | 含空域来源的唯一运动数 | 来源可重叠 |
| 5 | 含时域来源的唯一运动数 | 来源可重叠 |
| 6 | 含历史来源的唯一运动数 | 来源可重叠 |
| 7 | 空域运动最大 L1 距离 | 1/16 pel 整数单位，无空域为 -1 |
| 8 | 空域与时域最近 L1 距离 | 1/16 pel 整数单位，缺少任一来源为 -1 |
| 9 | 单一运动的最大独立空域 CU 支持数 | 整数 |
| 10 | 是否含最新 HMVP 支持 | 0/1 |
| 11 | 当前帧与参考帧 POC 距离绝对值 | 整数 |

距离使用经 AMVR 码字转换、再恢复到内部单位的运动。树不使用当前最终 MV、实际 MVD、
QP、编码器代价、原始像素、重建边界模板或浮点计算。

## 五套固定整数规则

树为整个 CU/参考列表实例选择一套规则，不直接输出最优候选索引：

| profile | 名称 | 有效候选权重 |
|---:|---|---|
| 0 | 均匀 | 全部 1，对应 mode 7 |
| 1 | 独立空域支持 | 至少两个独立邻接 CU 支持为 4，否则 1 |
| 2 | 跨来源支持 | 至少两类来源支持为 4，否则 1 |
| 3 | 最新历史支持 | 最近匹配 HMVP 年龄为 0 时为 2，否则 1 |
| 4 | 时域倾向 | 含时域为 4，否则含空域为 2，否则 1 |

权重是运动假设需要被覆盖的程度，不是直接按权重取前两项。固定规则本身不代表已经
证明有效；树根据离线训练损失选择它们在什么条件下使用。

## 加权联合选择

对当前 AMVR 码字精度的有效唯一候选 `c[k]`：

```text
profile = trainedTree(features)
B[k][i] = ExpGolombLength(c[k].x-c[i].x) + ExpGolombLength(c[k].y-c[i].y)
score(i,j) = sum_k weight(profile,k) * min(B[k][i], B[k][j])
```

预计算最多 64 个候选间距离，枚举最多 28 对，每对最多累加 8 项。全部为整数运算。
只用严格 `<` 更新最优候选对，同分时保持原始位置字典序；较早位置成为正式 MVP0。
余下候选保持原相对顺序，正式列表只取两个中心。

`ExpGolombLength` 是普通 AMVP 风格的运动码长估计，不是实际 CABAC bit，也不同于旧
报告的 bins 代理。算法不新增模板读取，不为八候选各执行一次完整 ME。

## 编码和解码流程

主要初始单向路径：

```text
标准 AMVP 两候选
 -> 原有整块预测代价预评估，一个普通 ME 起点
 -> 普通完整 ME
 -> 构造扩展池及元数据
 -> 共享决策树选择权重规则，加权八选二
 -> 原有两候选 MVP 复选，更新 MVD、bits 和 RD cost
 -> 写入原有正式 idx 和 MVD
```

解码端使用相同的已解码邻域运动、HMVP、参考关系和 CU 信息，重建同样的两个候选，
再根据 idx 与 MVD 恢复 MV。两端必须同时使用 mode 8 和同一模型节点表。

mode 8 虽为偶数，但沿用 mode 7 的主要 ME 后时点。仅 mode 2/4/6 显式在主要 ME 前
重排。双向迭代、哈希、整数 AMVR 及后续 RDO 仍有原有路径，不能将 mode 8 解释为整条
编码流程固定最终 MV 的实验。“无模板”仅约束新增选择算法，原有 ME 本身仍使用图像。

## 训练、验证和复现

本轮读取 472 份 mode 7 编码日志（13 个 Class B/C/D 序列、QP 22/27/32/37），
严格过滤后接收 1,968,450 条记录。最大树深度预先固定为 3，最小叶子 2,000 条原始
记录；最终部署树有 13 个节点、7 个叶子，模型 SHA256 为：

```text
95161dd9da1bd4e7735ac846f051ec26568eb13fd7ce328cbf3a4a76fed33d27
```

按完整序列留一验证，逐序列等权平均 MVD 估计码长相对均匀规则只减少
0.000025 bit/记录；部署模型在全训练集上的相应差值为 -0.000245 bit/记录。
部署模型约 93.545% 的记录选择 P0，非均匀规则占 6.455%，估计码长真正不同于 P0
的记录占 0.123854%。这些结果表明本轮五规则小树的离线改善极微弱，不构成压缩增益证明。

训练脚本、数据提取器、输入清单、质量过滤、节点 JSON、按序列评估和训练报告均位于
[`decisionTree`](../../decisionTree/README.md)。提取器直接调用生产共享特征和规则选择函数，
避免 Python 与编解码器的 AMVR 舍入、去重或同分处理不同。

离线标签固定 mode 7 最终 MV，比较每套规则选出的两项最小 MVD 估计码长与相同可选
真实候选集合的最小值。纯补零不进入训练 Oracle。SMVD、L1-zero、未显式传输的 MVD
及快照重放不一致样本不参与普通路径训练。该过滤无法证明旧快照完全等于真实排序时的
输入，现有日志训练结果应保留这一限制。

按完整序列留出验证，不能随机打散相邻 CU。最终全数据训练模型与留出评估的各折模型
需明确区分；离线损失降低不等于 BD-rate 增益。当前完整编码测试数据已位于
`/ssddata1/V_code/test_results/HHI_500_NNdimd_AMVP_mode_8`，实际 RD 效果与测试完整性见
[统一性能统计](../performance_all_modes.md)，应分别与 mode 0 和 mode 7 比较。

```bash
cmake --build build --target EncoderApp DecoderApp -j 6

bin/EncoderAppStatic -c cfg/encoder_lowdelay_P_nextRt500.cfg \
  -c cfg/per-sequence/RaceHorses.cfg \
  -i /ssddata1/testsequence/classD/RaceHorses_416x240_30.yuv \
  -f 3 -q 37 --amvpmode=8 --AmvpTrace=0 --SEIDecodedPictureHash=1 \
  -b out_mode8.bin -o enc_mode8.yuv > record_mode8.log

bin/DecoderAppStatic --amvpmode=8 -b out_mode8.bin \
  -o dec_mode8.yuv > decode_mode8.log

cmp enc_mode8.yuv dec_mode8.yuv
```

同名文件已存在时请更换输出名字。正式计时关闭打印，候选分析开启 `--AmvpTrace=1`。
