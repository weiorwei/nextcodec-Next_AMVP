# AMVP mode1 与之前实验的候选统计对比

## 结论

在固定各自编码结果最终 MV 的 oracle 统计口径下，mode1 改善了最终两个 AMVP 候选的覆盖质量：两候选 oracle 的平均 MVD L1 从 4.601737 pel 降至 4.475344 pel（-2.747%），平均 MVD bin 代理从 6.892101 降至 6.730093（-2.351%），两候选中存在零 MVD 候选的比例从 18.261526% 提高至 19.771321%（+1.509795 个百分点）。

额外候选严格优于当前两候选 oracle 的比例也明显下降：L1 从 24.428882% 降至 16.991531%，bins 从 21.391103% 降至 15.296774%。这说明重排已经把一部分原先位于扩展池后方的好候选移入了最终两个位置。

但 mode1 实际选中 MVP 的平均 L1 基本不变（4.811333 → 4.809089，-0.047%），平均 bins 从 6.988095 降至 6.869827（-1.692%）。因此目前最明确的直接收益体现在 MVD 二值化长度代理，而不是 MVD L1。

## mode1 内部还剩多少扩展空间

mode1 的当前两候选 oracle 为 4.475344 pel / 6.730093 bins；扩展到 4、8 和全池后的结果如下。

| 候选范围 | oracle L1/pel | oracle bins | 相对两候选平均节省 L1 | 相对两候选平均节省 bins | 严格改善块占比（L1 / bins） |
|---|---:|---:|---:|---:|---:|
| 4 | 4.095622 | 6.381532 | 0.379722 | 0.348561 | 12.793967% / 11.170824% |
| 8 | 3.998324 | 6.247456 | 0.477020 | 0.482637 | 16.634780% / 14.962195% |
| 全池 | 3.994015 | 6.236728 | 0.481329 | 0.493365 | 16.991531% / 15.296774% |

前 8 个候选已经覆盖全池剩余理论收益的约 99.1%（L1）和 97.8%（bins）。从 8 候选继续扩展到全池，平均只再降低 0.004309 pel 和 0.010728 bins，因此继续使用“最多 8 候选”是合理的复杂度折中。

不过只有 17.290616% 的块具有至少 8 个唯一候选，71.731855% 的块具有至少 4 个唯一候选。因此实现上应保持可变长度列表并去重，不能假设每个块都能得到 8 个真实不同候选。

## 候选来源变化

在 mode1 中，仍能严格击败两候选 oracle 的最佳额外候选按来源分布为：

| 来源 | L1 改善赢家数 | 占全部 L1 改善赢家 |
|---|---:|---:|
| 空域 | 201,587 | 41.16% |
| 时域 | 81,408 | 16.62% |
| HMVP | 206,722 | 42.21% |

之前实验的相应占比约为空域 22.38%、时域 19.18%、HMVP 58.45%。mode1 后剩余机会不再高度集中于 HMVP，说明一部分 HMVP/时域强候选已经被重排吸收到前两位；后续优化不能只关注 HMVP，空域候选仍贡献约 41% 的剩余 L1 改善赢家。

## 需要注意的现象

mode1 中实际选中 MVP 与“两候选 oracle”的差距为：

- L1：4.809089 - 4.475344 = 0.333745 pel；
- bins：6.869827 - 6.730093 = 0.139734 bins。

这不表示编码器选择错误。实际 MVP/MV 选择依据运动搜索与完整 RD cost，而 oracle 只是事后选择对最终 MV 的 L1 或 bins 最小者。不过它说明“候选进入前两位”并不自动等价于“实际一定选中 MVD 最短候选”，最终收益仍要看模板排序、ME 搜索结果和 RD 决策的共同作用。

## 最终判断

1. ARMC 重排方向有效：前两候选的 oracle 质量明显提高，额外候选相对前两位的剩余优势下降约 30%。
2. 实际 MVD bin 代理下降 1.692%，说明改善已经传递到实际选中结果；实际 L1 基本持平，收益并非来自简单的 L1 全面缩短。
3. 候选池仍有空间：全池相对当前两候选仍有 0.481329 pel / 0.493365 bins 的理论平均余量，但这是使用最终 MV 标签的 oracle 上界。
4. 8 候选足以覆盖几乎全部候选池上界，继续扩大到 8 以上的优先级很低。
5. 本报告不能代替 BD-rate。还需将 mode1 的 `results.xlsx` 与严格同配置的 mode0 锚点做 BD-rate、编码时间和解码时间对比，才能判断压缩效率是否真正改善。
