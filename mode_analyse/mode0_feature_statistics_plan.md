# mode0 + AmvpTrace：无模板 AMVP 32 维特征采集与统计

状态：**已实现采集与离线统计**。沿用 `--amvpmode=0`，仅由现有
`--AmvpTrace=0/1` 控制新增统计采集和打印。不新增模式编号。
新增日志格式为 `AMVP-STATS-* VERSION=1`。旧的 MVD/八池日志不能替代这一数据集。
本次尚未训练或部署新选择策略，正式多序列性能结论需要新采集的数据。
本轮编解码一致性、数学测试和完整短片统计结果见
[验证记录](amvp_feature_stats_validation.md)。

**2026-11-08更新**：默认输出已改为最终获胜CU，而不是全部UNI试探。使用
`--AmvpTraceScope=final`（默认）和可选`--AmvpTraceSamplePeriod=N`；旧的全部试探行为
通过`--AmvpTraceScope=trials`保留。此前2026-11-06的验证记录描述旧采集口径。
新版验证及日志缩减测量见 [最终输出与抽样验证](amvp_final_trace_validation.md)。

本规划针对普通平移 AMVP，目的是判断候选特征是否有助于选择第二个 MVP。
仿射候选的控制点、来源与历史模型不同，不纳入本版 32 维定义。

## 1. 模式约定

- 使用 `--amvpmode=0`，编码决策沿用原始流程。
- 保留原正式候选 `p0/b1`、原 MVP 预选、ME、最终 MVP 检查和 RDO。
- 在独立局部快照中收集扩展候选和统计信息，不把扩展池送回编码流程。
- 不执行 ARMC、TMR 或模型推理，不增加 ME，不改变历史表或码率代价。
- 新统计输出使用 stdout，由 `--AmvpTrace=1` 控制；`> record.log` 即可保存。
- Trace 关闭时跳过新增采集。mode0 Trace 开/关的码流、重建须逐字节一致。
- 生成的码流由原 mode0 解码，没有索引 sidecar，没有新增码流语法。

新增 32 维采集路径的启用条件为 `amvpmode == 0 && AmvpTrace == 1`。
`AmvpTraceScope=final|trials`控制输出范围，默认final；`AmvpTraceSamplePeriod=1`保留全部，
N表示按layer/POC/CU几何与`AmvpTraceSampleSeed`确定性地约保留1/N的CU。
两方向一起采样，未命中的CU在ME前即跳过新特征采集。其它模式的原日志不受这些mode0选项影响。
现有所有其他模式的 Trace 开关与日志保持其原有作用；本次不扩展它们的训练标签。
无需修改 `AmvpMode.h` 的模式支持范围、排序分支或解码器模式解析。

## 2. 样本单位及采集时点

默认`STAGE=FINAL`的一条query是最终获胜CU的一个活跃参考列表，特征使用该次搜索前
冻结的输入，标签使用最终写入码流的MV。双向CU的两个列表各一条，同CU只输出一次。
SMVD和强制L1零标记`LABEL_KIND=CONSTRAINED`，从普通独立MVD收益表排除并单独计数。
Merge、IBC、仿射不属于32维定义。

显式`AmvpTraceScope=trials`时，`STAGE=UNI`仍表示原有每次单向评估，包含最后没有获胜
的块、参考和AMVR。这一模式用于补充研究，日志可能很大；不要与FINAL口径混合解释。

每条输出使用独立 `QUERY_ID`，同时记录 POC、layer、CTU、CU 几何、refList、
refIdx、refPOC、imv、BCW、LIC 和编码尝试标识。相同坐标的重复 RDO 调用不直接合并，
因为它们的上下文可能不同。最终 CU 的 `interDir/mvpIdx/QP` 不作为特征。

接入位置：

1. `InterSearch::predInterSearch` 的每参考UNI循环中，原预选完成后、ME或复用前，
   冻结标准两项、原始运动来源和上下文。FINAL模式此时不计算全部32维，也不打印。
2. 本次搜索返回前，只将其最终活跃的一至两个参考快照注册为独立句柄，句柄随CU在
   RDO复制中传播。CTU完成后遍历`bestCS`，仅最终获胜CU按句柄解析快照，计算32维和标签。
   快照存活范围限当前CTU，输出后释放；使用全局唯一句柄防止过期/错误线程串样。
   FINAL输出ID另行连续分配，保留`SOURCE_QUERY_ID`追溯来源，避免分析器维护大量稀疏ID。
   trials模式仍在单向评估后立即打印。
3. 不从最终 CU 再构建训练特征，也不通过坐标反查历史缓存关联标签。
4. 不只在 `xCheckBestMVP` 内部采集：mode0 的 imv=1/2 分支可直接返回，不能为打印
   取消该返回或改变选择规则。

最终输出标为`MV_ORIGIN=FINAL_CODED SOURCE_STAGE=UNI`，保留`SOURCE_MV_ORIGIN`表明
输入快照的SEARCHED/L0_REUSE/BCW_CACHE来源。最终双向MV可已变化，标签按最终MV重算。
LIC、QP和BCW的采集值与最终值分别记录；它们不用于错误地拒绝运动快照。
快照缺失、上下文或predictor不匹配时明确打印`AMVP-STATS-SKIP`及原因，绝不在最终
历史状态重建输入补样。HashInterSearch等没有预ME输入的路径可能显式跳过，统计要检查覆盖率。

## 3. 独立备选池

`p0` 是本次查询原算法推导的第一候选；冻结仅针对本次 query。
备选池从原第二候选 `b1` 开始，最多 16 项，`p0` 不另外占用其中一个位置。

| 顺序 | 来源 | 原始项上限 |
|---|---|---:|
| 0 | 原第二候选 b1，始终保留 | 1 |
| 1 | 空间 A0、A1、B0、B1、B2，每位置一个匹配 MV | 5 |
| 2 | TMVP，C0 成功后不再取 C1，最多一个 | 1 |
| 3 | 原 AMVP 范围内的四条 HMVP，每条目标 list 后另一 list | 8 |
| 4 | 显式零 MV | 1 |

总上限为 16。新增局部结构使用独立容量，避免修改现有八候选模式和负模式 sidecar
依赖的 `AMVP_ARMC_MAX_NUM_CANDS` 常量。

先按当前 AMVR 舍入，再转 AMVR 整数网格、比较和稳定去重；相同 MV 合并所有来源。
额外候选等于 p0 时不新增备选，但仍保留其来源与统计票。b1 即使等于 p0 也保留回退项。
有效数量可变，不用纯补零凑满 16；显式零候选是有效假设。

当前 HMVP 的“前四条”是 LUT 索引 0..3，不是最新四条。LUT 最新记录在尾部，
满五条时索引 4 不进入首版池。第五条作为后续独立实验。
现有全量 trace 会采五条历史和 C0/C1 两个位置，不能直接当成这个新池。

## 4. 原始来源与统计集合

空间原始记录保留：探测位置、MV、匹配的来源 list、邻 CU 的 x/y/w/h。
历史原始记录保留：LUT index、年龄、来源 list、匹配参考 POC、MV。
同一候选的来源采用集合并集，不归给第一次提供它的单一来源。
`PROBE_INDEX` 的空间 0..4 表示 A0/A1/B0/B1/B2，时域 0/1 表示 C0/C1；
参考 POC 由查询头保存，所有原始源都经过该目标 POC 的匹配/时域派生。

- 空间集合 S：同一邻 CU 只取一个代表，按 A0/A1/B0/B1/B2 第一个合法命中确定。
- 历史集合 H：同一历史记录只取一个代表，优先匹配目标 list，否则另一 list。
- 不同独立单位即使运动相同，也保留各自的票。
- 中值使用分量中值，偶数样本取下中位数；离散度使用到中值 L1 距离的下中位数。
- 覆盖增益使用 S/H 的上述代表集合。
- 支持数量按独立邻 CU / 历史记录计数：该单位任一合法原始 MV 距离候选的
  AMVR 网格切比雪夫距离不超过 1 即支持，每个单位最多一票。
- 空集合对应数值特征取固定默认值 0，并由 F31/F32 显式表示不可用。

## 5. 32 维输入及历史列表诊断字段

| 特征 | 定义 |
|---|---|
| F01–F08 | c 相对 p0、b1、S 中值、H 中值的水平/垂直差 |
| F09–F10 | S/H 上相对原候选对的覆盖增益，Q2 整数 |
| F11–F12 | 支持 c 的独立空间 CU / 历史记录数 |
| F13–F14 | 支持 p0 的独立空间 CU / 历史记录数 |
| F15–F16 | S/H 的运动离散度 |
| F17–F21 | 左侧、上侧、时间、历史、零运动标志 |
| F22 | 精确提供该候选 MV 的最近历史年龄，无历史取 -1 |
| F23 | 空间/历史来源中存在另一 list 支持且不存在目标 list 支持 |
| F24 | 目标参考是否长期参考 |
| F25–F26 | floorLog2(W/H) |
| F27 | 平移 imv |
| F28 | 当前 POC 减目标参考 POC，有符号并按固定范围裁剪 |
| F29 | 目标参考列表 0/1 |
| F30 | 是否 B slice |
| F31–F32 | S/H 的有效独立单位数 |

平移 imv=0/1/2/3 的一个网格单位分别为 1/4、1、4、1/2 像素。
支持阈值为一个网格，需在统计中单独检查 imv=2 的四像素支持范围。

为判断量化是否损失区分能力，同时保存未压缩整数值和模型输入值。
已冻结 `SIGNED_LOG_V1`：距离绝对值 <=4 时保留精确值，否则编码为
`sign(d)*(5+floorLog2(abs(d))-2)`；F01–F08、F15–F16 使用该量化。
F28 使用 [-32767,32767]，其余模型输入按 int16 范围饱和。
F09/F10 的平均覆盖增益乘4后，采用最近整数、半值远离零的舍入；空集合返回0。
运行时和 Python 独立验证实现相同的明确整数规则，避免各语言默认舍入差异。
码长代理在原 AMVR 网格上计算，再对输出特征量化，不能先压缩 MV 再计算码长。

历史列表是本轮重点，额外保存诊断字段，不能仅依赖 F23：

- `H_LIST_MASK`：0 无历史、1 仅目标 list、2 仅另一 list、3 两者都有；
- 精确来源的同/另一 list 独立历史记录数及最小年龄；
- 同/另一 list 的邻近运动支持数（与精确来源计数区分）；
- 每条原始历史记录的 index、age、sourceList 和 MV。

两个方向必须经过参考 POC 匹配；另一 list 不代表另一张目标参考图片或相反运动方向。
这些字段目前先用于统计，是否扩展模型输入由消融结果决定。

## 6. 特征优先级与检验问题

以下优先级表示采集和验证的顺序，是研究假设，不是已经测出的模型重要性。
全部 32 维及必要来源原始信息应一次采齐，避免早期按假设删字段后反复重编码。

| 优先级 | 原特征编号 | 重点问题 | 建议统计 |
|---|---|---|---|
| A 核心 | F09–F10 | 替换第二槽是否改善运动覆盖 | 按正/零/负及幅度分箱，检查 gain 的正负概率、均值和实际选一后的净收益 |
| A 核心 | F11–F14 | c 的支持是否可靠，p0 是否已经覆盖主运动 | c/p0 支持数交叉表，分别检查空间/历史；再与覆盖增益交叉 |
| A 核心 | F22–F23 | 历史新旧、跨列表来源能否提供增量信息 | 年龄、跨 list 标志、H_LIST_MASK 联合分组，控制 imv/POC距离/目标list |
| A 核心 | F01–F04 | c 与已有 p0/b1 的关系是否能预测互补收益 | 有符号差值分布、幅度分箱、接近 p0 与远离 p0 的条件收益 |
| A 必需口径 | F31–F32 | 空间/历史统计是否可用、是否有足够票 | 0/1/2/更多独立单位分组；空集合与真实零值分开 |
| B 辅助 | F05–F08 | 贴近主运动中值是否有利，何时损害互补性 | 与 F09/F10、p0 支持交叉；有/无该组的留序列消融 |
| B 辅助 | F15–F16 | 运动分歧程度能否决定来源选择策略 | 低/高离散度内分别比较历史 list、来源和支持数的收益 |
| B 辅助 | F17–F21 | 来源集合和零运动能否表征可靠性 | 来源掩码联合分组，避免互斥归因；检查独有候选贡献及元数据增量价值 |
| C 上下文 | F25–F29 | 哪些尺寸、精度、参考距离和列表适合替换 | 分层结果及与 A/B 组的交互消融 |
| D 先看分布 | F24、F30 | 长期参考/B slice 在当前数据中是否变化 | 缺失率、取值频率、逐序列分布；常量时不据此宣称其他数据上无用 |

F13/F14、F24–F32 是同一 query 内共享的量，不能仅因它们在 query 内不变化而删除。
它们可以决定替换阈值、调节候选特征的重要性；应检查与候选特征的交互。
普通单个线性加分模型中，共享上下文项对同 query 排名会相互抵消，这与树中的条件分支不同。

### 历史来源优先专项

1. 按无历史/仅目标 list/仅另一 list/两者支持四组分别报告候选数和有该组候选的 query 数。
2. 对每个候选报告 `gain>0`、`gain=0`、`gain<0` 比例、含负值的平均 gain，以及收益和损失幅度。
3. 在同 query 中比较不同来源候选，按 imv、目标参考列表、参考 POC 距离分层；
   避免把某组出现更多、候选更多误认作该组更可靠。
4. 交叉历史年龄、历史支持数和 p0 的历史支持 F14，判断另一 list 是否主要提供互补运动。
5. 分开测两类贡献：删除仅由该来源提供的独有 MV 后，池内最优码长损失；
   保留全部 MV 但不使用该来源元数据时，验证集选择净收益下降多少。
   同 MV 多来源共享时，删除一个来源不能把其他来源仍可提供的 MV 一并删掉。
6. 历史 mask 只作为诊断和候选扩展特征的依据，首轮不擅自替换 F23，保持32维原定义。

### 统计与重要性判定

先检查每维的可用率、常量率、取值范围和量化碰撞，再做单维分箱与交叉表，最后做特征组消融。
单维相关性小不意味着它与其他特征交互时无用；树的分裂次数也不直接等于实际净收益。
小模型仅作为离线统计工具，使用同一候选池与回退策略，按完整视频序列划分训练/验证。
同序列所有 QP、片段必须在同一侧。阈值和量化参数在训练/验证中冻结后再评价留出序列。

至少报告：每 query 选择后的平均 gain、退化 query 比例、损失幅度、相对池内最优的 regret、
逐序列结果和已执行/复用结果分层。并列最优不能只给首个候选记成功。
正收益总量与固定 MV Oracle 总量的比值可作上限捕获率，分母为零时标记不可用。
置信区间按视频序列等独立分组重采样，不能把同一 query 的多个候选当独立样本。
离线固定 MV 收益不等同于完整编码 BD-rate。

## 7. 标签

最终输出使用最终MV作为v*；trials输出使用本次UNI评估结果。标签只用静态纯函数计算：

```
R0  = EG(v* - p0) + originalIndexCost(0)
Rb  = EG(v* - b1) + originalIndexCost(1)
Rc  = EG(v* - c ) + originalIndexCost(1)
Jb  = min(R0, Rb)
Jc  = min(R0, Rc)
gain = Jb - Jc
```

EG 先分别把最终 MV 和 predictor 转到当前 AMVR 网格，再计算两个分量的码长估计。
沿用两个正式槽位的索引代价，不给备选池中的 CID 计费。

每条同时保存实际原流程选中的 MVP、idx 和其估计码长，与反事实基准 Jb 分开。
特别是原整数 AMVR 路径的最终检查可能早退，不要求实际选中代价必然等于 Jb，
更不能为了使其相等而修改编码。

结果仅用于打印，绝不写回 bits、cost、MV、MVD、MVP 或 HMVP。
禁止为了标签调用 `m_pcRdCost->setPredictor/setCostScale` 等会改变搜索状态的接口。
无需 CABAC 上下文修改。第一阶段标签是 EG 估计收益，不是实际 CABAC bit 或 BD-rate。

由于 b1 始终保留，固定 MV 的池内最优收益应非负，b1 自身的 gain 应严格为零。

## 8. 日志与脚本规划

在选定输出阶段，以一个不可交错的记录组输出冻结快照和标签：

```
[AMVP-STATS-QUERY] VERSION=1 QUERY_ID=... STAGE=FINAL MV_ORIGIN=FINAL_CODED SOURCE_STAGE=UNI LABEL_KIND=... P0=... B1=... CAND_COUNT=...
[AMVP-STATS-RAW] QUERY_ID=... KIND=SPATIAL/HISTORY/TEMPORAL ...
[AMVP-STATS-CAND] QUERY_ID=... CID=... MV_INT=... H_LIST_MASK=... F01=... ... F32=... JB_EST=... JC_EST=... GAIN_EST=...
[AMVP-STATS-END] QUERY_ID=... RAW_COUNT=... CAND_COUNT=...
```

表头记录 schema、参数、特征定义/量化版本。终止标记及数量用于检出截断日志。
最终真实MV只放标签字段，不混入模型输入。试探和最终query具有明确STAGE，约束样本
单列；`trace_skip_summary.csv`记录没有可用冻结快照的最终AMVP及其原因。

`decisionTree/feature_analysis/` 包含：

- schema、采集说明、日志提取与完整性校验；
- 历史 list 类别 × 年龄 × 支持数的查询数、正收益率、平均正/负收益；
- F09/F10 分箱与真实 gain 的对应关系；
- 独有候选移除后的 Oracle 码长损失（共享 MV 不重复归因）；
- 按完整视频序列留出的特征组消融及选择策略净收益；
- 原始候选数、量化后取值数、缺失/恒定率与逐序列分布。

每查询总权重相同，避免备选多的查询、重复 RDO 或缓存复用占据过大权重。
并列最优要显式处理；先按 sequence、QP、imv、POC 距离、目标 list 和结果来源分层，
不把候选级相关系数直接解释成编码收益。当前 QP 可作离线分组元数据，不进入首版特征。

## 9. 使用、实现位置与验收

编码（普通平移统计，原有编码参数保持一致）：

正式批次可将输入换成日志目录，采用 `Sequence_QP_segment_enc.log` 的文件名以恢复序列身份。
`--sequence` 仅用于明确给定单序列日志；不要将不同视频强行标成同一序列。
支持 `.log.gz`；`--max-queries N` 用于快速检查，会在报告中标记统计未覆盖完整输入。
旧日志没有新 schema 时不会伪造32维，若无有效新查询将返回非零状态。

核心文件：

- `CommonLib/AmvpFeatureStats.h`：无 codec 状态和像素依赖的纯整数特征与运动码长代理。
- `EncoderLib/AmvpFeatureTrace.h`：只读冻结原始来源、候选和元数据，搜索后打印。
- `EncoderLib/InterSearch.cpp`：mode0 Trace 开关和 UNI 前/后接入，显式标记缓存来源。
- `tools/test_amvp_feature_stats.cpp`：独立数学与边界验证。
- `tools/test_amvp_feature_trace_codec.py`：旧二进制、Trace开/关的码流和重建回归。
- `decisionTree/feature_analysis/`：日志校验、统计、可解释选择规则及说明。

实施及验收步骤：

1. 新增独立只读候选/来源结构、固定统计规则和32维提取器；共享纯码长计算。
2. 在 mode0 中接入现有 Trace 开关，在 UNI 前冻结、后补标签，明确复用路径。
3. 增加版本化可解析日志和离线提取/统计脚本。
4. 做边界验证：双 list 同 MV、同历史记录不同 MV、同邻 CU 多探测、p0=b1、
   空 S/H、负增益、所有 imv、TMVP 回退、满五条历史及来源合并。
5. 同二进制同参数比较 mode0 Trace关、Trace开，码流和重建逐字节相同；
   使用 mode0 解码，检查重建及 MD5。采样不得破坏 BCW、L1 复用及双向场景的原编码。
6. 先短片检查日志完整性、每候选标签和开销，再采正式多序列数据。
7. 最后决定哪些特征进入模型；采集模式本身不部署候选选择策略。

默认只输出最终编码CU。trials模式覆盖原算法已经尝试的UNI查询，正式分析必须区分口径。
源码保留全部32维及原始来源，不通过删掉关键特征来控制体积；主要依靠最终赢家过滤及CU抽样。
旧巨日志可用`decisionTree/feature_analysis/sample_trace.py`按整query抽样压缩，后续复用小文件。
抽取整文件样本仍需顺序读取一次；`--max-scan-bytes`只读前缀时明确标PARTIAL。
旧日志没有保存赢家句柄，不能仅按坐标/MV匹配可靠地恢复FINAL数据。
打印开关不承担算法参数作用，已有模式和解码流程保持兼容。
