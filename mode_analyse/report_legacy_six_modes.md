BD-rate 为负表示相对 mode 0 节省码率。mode 0 是锚点，表中记为 0。最终是否有效应以 BD-rate 为准；平均 MVD 和 bins 只能解释运动预测差分，不能直接替代实测码率。

## 结果解读

- 在不使用 sidecar 的实用模式中，mode 2 的 BCD 宏平均 Y BD-rate 为 -0.106%，mode 1 为 -0.066%；mode 2 数值上多节省 0.040 个百分点。两者分别在 11/13 和 10/13 个序列上取得负 Y BD-rate。该差距较小，若用于正式结论，建议增加独立重复运行验证波动。
- mode 2 的平均 MVD bins 代理为 6.682，相对 mode 0 下降 4.39%；这与更短的运动差分方向一致，但实际收益仍以 BD-rate 为准。
- 三个 sidecar 上限模式中，mode -2 的 Y BD-rate 最低（-0.595%），mode -3 为 -0.557%，两者只差 0.038 个百分点；mode -3 相对 mode -1 数值上再改善 0.251 个百分点。mode -3 用一次普通 ME，mode -2 对多个唯一候选分别执行完整 ME，因此二者主要体现“单起点模板预选”和“多起点搜索上限”的复杂度—性能差异。
- mode -3/-2/-1 的最优 Oracle MVP 仍位于扩展池原始位置 0/1 的比例分别为 61.224%、65.287% 和 71.884%；相应的 idx 2..7 使用率为 38.776%、34.713% 和 28.116%。这说明多数记录的最优候选仍在前两项，但后六项也确实包含可缩短 MVD 码长的候选；这些真实索引依赖场外 sidecar，不能视为无开销编码工具。
- 编解码时间来自不同批次日志的 ET/DT 总和。负变化不能直接证明算法加速；mode -2 的编码 ET 为 +29.39%，与多起点完整 ME 的额外复杂度方向一致。mode -3 与 mode -1 的实现还存在低延迟 RPL1 快速复用路径差异，不能把二者差值完全归因于候选预评估范围。
- 各模式选择到的 CU 集合和 AMVP 记录数不同，因此全局 MVD 均值不是同一批块的配对比较。候选快照统计还受 `FOUND=yes` 条件抽样影响，不能据此横向判断负模式候选池本身优劣。

### 扩展到 8 候选后，最优候选仍位于原始 0/1 的比例

该指标直接读取负模式 sidecar 中保存的真实 Oracle 索引，计算公式为：

```text
Oracle idx0-1比例 = Oracle索引为0或1的记录数 / 全部有效Oracle记录数 × 100%
```

| mode | 有效 Oracle 记录 | Oracle idx0/1 记录 | idx0/1 比例(%) | Oracle idx2-7 记录 | idx2-7 比例(%) |
|---|---:|---:|---:|---:|---:|
| -3 | 5,568,026 | 3,408,991 | 61.224409 | 2,159,035 | 38.775591 |
| -2 | 4,847,191 | 3,164,596 | 65.287215 | 1,682,595 | 34.712785 |
| -1 | 4,340,618 | 3,120,209 | 71.883981 | 1,220,409 | 28.116019 |

这里的 0/1 是负模式扩展池中的原始前两个位置，通常对应标准 AMVP 候选；“最优”指固定
最终 MV 后，按实验中的原始 AMVP 风格 MVD 码长估算选出的 Oracle MVP。该比例不是候选
快照覆盖率：它使用全部有效 sidecar 记录，不依赖 `[AMVP-CAND-SET]` 是否匹配成功。
mode 0/1/2 不使用 Oracle sidecar，因此该指标记为 `NA`。

## 数据范围与完整性

统计严格限定六模式共同且完整的 13 个 Class B/C/D 序列，共 65 个序列-QP 点和每模式 590 个分段任务。部分实验目录中的额外 Class A 日志未纳入，因为它们不属于六模式共同数据集。

编码 RD 数据按逐帧 POC 聚合：第 0 段保留 POC 0，后续段丢弃重复的 POC 0；码率由保留帧 bits 重算，PSNR 用日志中的十六进制 double 精确求平均，复杂度使用相同去重规则下的 ET/DT。完整性明细见 `tables/integrity.csv`。

本次产物默认复用同口径 `results.xlsx`；缺少该文件的模式直接从原始 POC 日志重算。 MVD/candidate/oracle trace 的记录数与错误检查见 `tables/trace_integrity.csv`。

## AMVP 候选统计的限制

- mode 0/1/2 不使用场外 oracle；其实际候选快照覆盖率仍以 `tables/candidate_global.csv` 为准。
- 负模式候选快照覆盖率分别为：mode -3 为 31.816567%，mode -2 为 54.867853%，mode -1 为 65.231683%。`FOUND=no` 不是随机缺失：当真实 oracle MVP 与正式位置 0/1 不同，正容易缺少快照。
- 因而 mode -3/-2/-1 的候选池大小、来源比例、oracle4/oracle8 等只适用于 `FOUND=yes` 条件子集，不能与非 oracle 模式横向排名，也不能按覆盖率插补。
- sidecar 的 oracle idx 分母包含所有 translational AMVP 记录（包括推导 MVD）；MVD 均值与 bins 的分母是显式 MVD 记录。两类百分比不要直接相除。
- `mean_mvd_syntax_bins_proxy` 只是 MVD 语法二值化数量代理，不含上下文概率、残差、模式标志等，不等于实际 bit。
