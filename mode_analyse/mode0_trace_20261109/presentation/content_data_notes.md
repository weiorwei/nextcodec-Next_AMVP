# AMVP特征汇报数据说明

- 全量 3,528,046 条最终query，普通 2,369,326；用于准确Oracle潜力、原0/1关系、AMVR/基础QP分组。
- 1/20离线整query抽样得到176,559，排除58,059约束，普通118,500；全部32维、来源与标签独立重建，0异常。
- 全量基准8.279195→Oracle7.640580，潜力0.638615 bit/query；20.393310%可严格改善，79.606690%原对已经达到池内最小值（允许并列）。
- 所有收益是固定最终MV的EG运动码长代理（含原slot索引代价），不是CABAC、bins或BD-rate。
- F11/F12支持分箱表示候选级描述：每query新增备选总权重1；不能把正收益比例当作实际选择规则的命中率。
- 六核心规则在13序列逐序列均为负。最大空间覆盖−0.093468、空间支持−0.180422、历史覆盖−0.641857、历史支持−0.596574、最近可用历史−0.721384、联合覆盖−0.398346 bit/query。
- 历史源可提供67.48%的总Oracle潜力；删除历史独有新增候选损失0.313350 bit/query。它表明有候选价值，不表明历史优先有效。
- 历史mask1/2/3为仅目标list/仅另一list/双list共同支持；另一list也已匹配目标参考POC。mask不是F23（F23还包含空间来源）。
- 双list共同支持新增候选仅914query可用（0.771%）；不能用稀少样本宣称可靠优势。
- 历史年龄是相对于完整LUT的年龄，原AMVP范围为前4槽；满5槽时最新索引4未进入池。历史slot表按记录/list分组，同query可反复出现，不能叠加为不同query数。
- F24长期参考恒0、F30是否B slice恒1，仅表示本批数据无法评价其区分能力。
- 没有训练新模型、没有整序列留出消融，因此不可制作“32维重要性排名”。可使用“观察到的区分能力”“直接规则净收益”“来源Oracle潜力”三种分开的表达。

字段详情和所有绘图精确值见deck_data.json，各组均附source。运行extract_deck_data.py可从已有CSV/JSON重建。
