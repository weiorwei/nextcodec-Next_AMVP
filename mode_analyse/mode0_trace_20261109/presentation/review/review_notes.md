## 每页必须保持的区别

1. **全量与抽样**：3528046条FINAL query，2369326条普通、1158720条约束；全量精确核验EG标签和结构。32维、来源、规则结果使用1/20 query样本：176559抽中、58059约束排除、118500普通。
2. **query与CU**：一条query是最终CU的一个活跃参考列表；BI可两条。离线哈希按query保留整候选组，不保证BI两条同时保留。不要写“118500个独立CU”。
3. **候选与标签**：p0/b1是原候选；替换池上限16，计入b1、不单独计p0。不是此前mode−1的固定8池。正式列表研究目标仍为两项，不增加正式索引。
4. **收益单位**：EG MVD+原两槽索引的估计码长，固定最终MV。不是真实CABAC、不是bins、不是BD-rate。全量运动EG代理约7.713%潜力尤其不能标为“节省7.7%码率”。
5. **三种证据**：单维分箱关联≠确定性规则选一的净收益≠离线Oracle上界；本轮没有训练或做留序列消融，不能声称正式“特征重要性排名”。

## 特征定义易混淆点

- **F21**：候选运动为零`c==(0,0)`的属性，不限于“显式零MV来源”。来自空间/历史的真实零也为1。
- **F23**：空间和历史来源中，只有另一list、没有目标list精确提供该候选。不是`H_LIST_MASK`；后者仅描述历史list支持，取0/1/2/3。
- 另一list也必须匹配目标参考POC，不能理解成反向运动或错参考。
- F11/F12支持允许网格L∞距离≤1，不是精确MV出现次数；一个独立CU/历史记录只计一次。
- F22为精确提供候选的最近历史年龄。原算法检查LUT索引0..3，满5条时不含最新索引4；“年龄最小的可用历史候选”不能简称完整HMVP的最新候选。
- F09/F10为Q2，4代表1估计bit；图上若显示原始值必须写Q2，否则除4后写bit。
- MV距离按当前AMVR网格，不能直接把不同imv下的原始距离当成同一像素单位比较。

## 适合讲与不适合讲的结论

| 可以讲 | 不应讲 |
|---|---|
| 历史来源提供大量新增候选潜力 | 历史来源应无条件排在前面 |
| 同list/另一list候选的正收益比例接近 | 两者在所有上下文具有相同性能 |
| 双list共同支持组正收益比例较高，但只有914queries可用 | 双list共同支持是已验证最佳特征 |
| 支持数较多的组正收益概率较高 | 直接选支持最多的候选可以省码率 |
| 当前最大F09/F10规则平均为负 | 所有覆盖特征或所有无模板方法均无用 |
| F24/F30在当前RA候选样本恒0/恒1 | 这两个特征在任何编码配置都没有价值 |
| F01–08/F15–16已采集且有变化，适合作为后续联合模型输入 | 这些特征已经证明能提高BD-rate或比历史更重要 |
| imv1/2/3组Oracle机会高于imv0，是未调整的分组相关性 | 改成某个imv一定会增加收益 |

## 讲解F01–08与F15–16的可靠素材

来自候选分布表（386764新增候选行，不是query数）：

- F01–08都有明显取值变化；量化后约28–29种取值。空间中值相关特征缺失5.436%，历史中值相关缺失1.102%。这些是可用性/分布信息，不能直接换算成模型效果。
- F15空间离散度原始0..814、量化13种；F16历史离散度0..1157、量化14种。较大离散度组的任意候选替换平均收益往往更差，但尚未做独立可部署触发规则。
- F24在本候选样本原始最小/最大都是0；F30最小/最大都是1。保持32维ABI，后续训练可屏蔽常量维；不必因此改采集代码。

## 最后建议的实验顺序

1. 保留p0与b1回退，针对错误替换训练“净收益/置信度”，而非强迫每个query都替换。
2. 使用候选对增益标签，所有候选按query平衡；全部QP与片段按完整视频序列留出。
3. 同时报告净收益、获益总量、损失总量、替换率和逐序列稳定性；不能只看命中率。
4. 固定MV验证有效后，再部署并做统一构建、关闭打印的闭环BD-rate。
5. 边界长度支持代理是新假设，现有五点日志不是完整边界运动扫描。本PPT不能展示尚未做的几何权重收益。
